# 测试桩按平台可执行形式调用

2026-09-15（#388）：需要子进程的测试桩（如假 yt-dlp `rust-core/tests/fixtures/fake_ytdlp.py`）一律经测试装配层的 helper 取可执行路径（`tests/common` 的 `fake_ytdlp_executable()`），不把脚本路径直接交给进程启动接口。类 Unix 直接执行脚本；Windows 由 helper 在 cargo 测试临时目录写一个 `.cmd` 启动器，以解释器的绝对路径转交脚本。

**Considered Options**

- **按平台禁用端到端用例并登记**：否决。跳过等于 Windows 上这一层没有防线。
- **给桩提交一个平台外壳（.cmd）**：否决。编排层方言拦截会报红，且被跟踪的外壳要记住解释器位置。
- **在测试装配层按平台改写调用形式**：采纳。产品代码不动、断言不削弱、新增用例走同一个 helper 不会重复踩坑。

**Consequences**

- 启动器路径在进程内保持稳定：解析器全局缓存 yt-dlp 路径，放进单个测试的临时目录会在该测试结束后失效。
- 启动器写解释器绝对路径：Windows 的 `python` 别名经 LOCALAPPDATA 解析，而日志用例会重定向它。可用 `RHYTHM_TEST_PYTHON` 指定解释器。
- 桩起不来时 helper 断言「stub not runnable」，与产品解析错误区分。
- 依赖「可执行文件消失即 spawn 失败」的用例（RS-14）在 Windows 上无法用启动器构造：删掉 `.cmd` 后 `cmd.exe` 仍能启动。该用例按 ADR-0001 在 Windows 上显式禁用并进红测登记，其余平台照常运行。
