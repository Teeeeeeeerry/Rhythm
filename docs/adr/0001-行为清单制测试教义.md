# 行为清单制测试教义

2026-08-13 经 grilling 会话（17 项决策）确定：以**行为清单**定义测试完整性——每模块一份清单（`docs/testing/behavior/<模块>.md`），条目分主路径/边界/错误路径三层并标 P0/P1/P2，清单上每一项都必须有自动化测试，行覆盖率只作参考；测试暴露出的产品缺陷**只登记不修**（GitHub issue），对应测试以**红测禁用**形式入库（`XCTSkip`/`#[ignore]`/`Catch2 SKIP()` + issue 链接），缺陷修复时解禁。

**Considered Options**

- **覆盖率阈值制**（如行覆盖率 80%）：否决。驱动凑数测试与删代码，无法回答"哪个行为没有被守住"。
- **发现即修**：否决。测试工作与产品修复耦合，单次改动面过大，缺陷修复无法独立审阅。
- **行为清单制**：采纳。清单是交付物，"全面"因此可验收。

**Consequences**

- 测试套件中会长期存在带 issue 链接的禁用测试——这是有意为之的已知缺陷标记，不得无端解禁或删除。
- P0 条目是该模块票的合并门槛；P1 同波次内完成；P2（错误路径）只断言"错误被正确上报"，可顺延至后续波次。
- 与 `docs/deep-testing-plan.md` 的 L0–L4 主题色体系互补：后者管"颜色对不对"，本教义管"行为对不对"。
- 解锁测试的结构性改动限于**最小接缝**（trait/protocol 注入点），不得改变产品行为。
